Channel Discovery Replatform

Replace the browser-scraping fleet behind Telegram channel discovery with a managed rendering API, cutting fixed infrastructure cost by ~92% without losing the search results analysts rely on.

1 · Problem

Darkmap turns an analyst’s search term into a ranked list of Telegram channels likely to be leaking data about it. Discovery runs six tuned search queries against a curated Google Programmable Search Engine, two result pages each — twelve requests per search.

Google blocks repeated automated access, and measurement puts the limit at roughly 10–15 requests per IP address. A single search therefore nearly exhausts one address. The platform solved this by spreading requests across six containerised services and eighteen tasks, each with its own public address behind its own load balancer.

That architecture is correct for the constraint and badly mis-sized for the traffic. It was built for a product doing thousands of searches; it serves 3.5 per day.

The availability finding reframed the project. An idle-shutdown scales the fleet to zero after 30 minutes. No code path restarts it — verified across the backend, both clients and their built bundles. At 3.5 searches/day the fleet is cold most of the time, so the incumbent’s “3-second” latency describes a state users rarely encounter. This moved latency from a hard requirement to a trade-off.

2 · Goals & non-goals

Goals

  1. Eliminate fixed cost. Discovery spend should scale with usage, not with pre-provisioned capacity.
  2. Preserve result quality. Analysts must not lose channels they would previously have found.
  3. Remove the CAPTCHA class of failure rather than continue paying to work around it.
  4. Keep the product available without a manual warm-up step.
  5. Reduce operational surface — fewer components to maintain, patch and reason about.

Non-goals

  • Not improving on 3s warm latency. A managed renderer is slower per request. Accepted deliberately — see §6.
  • Not re-tuning the six search queries. They are the product’s accumulated IP and must pass through unchanged, quirks included.
  • Not changing the API contract. Any client change widens blast radius for no user benefit.
  • Not fixing Telegram message retrieval. Separately broken (expired sessions, returns 502). Out of scope, tracked independently.
  • Not migrating the AI ranking layer. Works well; untouched.

3 · Requirements

R1
Identical response contract

The replacement returns the same shape as the incumbent so no client changes are needed.

AC: response contains channel_names and channels[] with name, title, description, url; ordering consistent between both keys.
P0
R2
No loss of security-relevant channels

Coverage is judged on the channels analysts act on — breach forums, leak brokers — not raw result counts, which include news and exam-prep noise the ranker already discards.

AC: for a baseline query set, 100% of security-relevant channels found by the incumbent are returned. Verified against a captured pre-migration baseline.
P0
R3
Search queries preserved verbatim

Includes known quirks — curly quotation marks, a missing space, a regex branch that collapses multi-word terms — all tuned or tolerated deliberately.

AC: automated test asserts each query string byte-for-byte, including quirks.
P0
R4
Terms containing reserved characters must work

An ampersand in a term (AT&T) previously truncated the query, so the engine silently searched for "AT and returned confident, wrong results. This class of bug must not return.

AC: AT&T returns channels whose descriptions mention AT&T; test asserts the URL carries the encoded character and no fragment.
P0
R5
Every channel carries a description

The AI ranker scores on the result snippet. Missing descriptions silently degrade ranking rather than failing loudly.

AC: withDescription equals total channel count on every search; logged per request.
P0
R6
Instant rollback

Reverting must not require a deploy or an infrastructure change.

AC: unsetting two environment variables restores the previous upstream; no code change.
P0
R7
Predictable latency under the gateway ceiling

Requests run in parallel, so total latency equals the slowest one, and the vendor’s per-request time varies 3–19s. Variance, not the median, is the user-facing problem.

AC: p95 per search comfortably under the 29s API gateway timeout; spread narrower than the incumbent’s.
P1
R8
Transport failures must not silently drop results

~1.7% of calls fail at transport level. A dropped request costs channels with no visible error.

AC: per-request retry; failure count logged per search; a failed request never returns a partial set as if complete.
P1
R9
Support the advanced-search path

One query is built at runtime from user-supplied include/exclude keywords rather than a fixed template.

AC: presence of keyword parameters switches to the dynamic query; contract unchanged.
P1
R10
No public unauthenticated compute

Any endpoint that spends money must require a credential.

AC: requests without or with an incorrect key return 403.
P1

4 · Options considered

Five approaches were evaluated against a captured baseline of live results. The decisive finding was structural:

Anything that renders our curated search engine preserves the results. Anything that queries Google generally does not. Our engine is restricted to a handful of Telegram directory sites, and that curation is the asset. A general web-search API reproduced only 33 of 72 channels — and adding result pages flattened the overlap while piling on irrelevant channels, so it was not fixable by paging.

5 · Decision log

DecisionRationale
Judge coverage on security-relevant channels, not totalsRaw overlap was 0.58 while security-relevant coverage was 13/13. The gap was news, sports and exam-prep channels the ranker scores near zero and the client never shows. Optimising raw overlap would have rejected the right answer.
Keep the response contract frozenZero client changes, so rollback is an environment variable and the blast radius is one service.
Use the query-string URL form, not the fragment formThe vendor URL-decodes before navigating, so an ampersand inside a fragment truncated the query — silently reintroducing a previously-fixed bug (R4). The query-string form has no fragment to mangle.
Hedge slow requests instead of buying concurrencyNo queueing existed to remove: 10 requests, 10 workers, zero rate-limit errors. A higher tier would have bought 1–2s for $30/mo. Duplicating stalled requests cut the spread from 10–20s to 12.6–14.2s for ~$0.40/mo.
Standard library only, no browserRemoves the container image, the registry dependency and the compiled-parser build step. Cold start measured at 143ms; deploys are a plain archive.
Snapshot before decommissioningFull configuration of the retired fleet is committed, with a note that its templates pin older task revisions than were live — rebuilding from them naively would downgrade.

8 · Rollout

  1. Baseline capture. Record live results for a query set covering a common term, a term with a reserved character, and a multi-word term exercising the regex branch.
  2. Build in parallel. New function deployed alongside the fleet on a new route. No existing resource modified; all four incumbent routes verified still healthy afterwards.
  3. Verify against baseline. Contract, coverage, description completeness, the reserved-character case and the advanced path, then end-to-end through the real service including AI ranking.
  4. Cut over by configuration. Two environment variables switch the upstream. Rollback is removing them.
  5. Observe in production. Real searches; confirm the log line reports the new upstream, full description coverage and expected timing.
  6. Decommission. Snapshot, then delete services, load balancers, target groups, the idle-shutdown function, its scheduler, three alarms and the unauthenticated endpoint. Re-verify the product after each step.
Found during decommissioning. A cost review scoped to one AWS region had missed a load balancer in another, live since August 2024 with every target unhealthy and no tasks behind it — $25.25/month for 13 months. Also removed: a public unauthenticated endpoint that started 18 billable containers on request, and 39 unused container repositories. Cost reviews are now explicitly all-region.

  • Open  Credentials and session files remain baked into a retained container image. Rotate with the Telegram session work.
  • Open  Telegram message retrieval still returns 502 on expired sessions. Separate track, and now the largest remaining gap in the user journey.
  • Open  Behaviour above ~10 concurrent users is modelled, not measured.
